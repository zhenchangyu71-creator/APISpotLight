# 查找页面接口

**APISpotLight · 阶段 1 · MCP: `find_page_apis`**

## 前置检查

1. 确认 Cursor MCP 中 **`api-spotlight`** 服务可用（工具列表应含 `find_page_apis`、`export_confirmed_apis`、`test_torna_connection`）。
2. 若使用 Torna 项目链接，确认环境已配置 `TORNA_TOKEN`（勿在对话或工具参数中粘贴 token）。

## 收集参数

向用户收集（缺一不可则先追问）：

| 参数 | 必填 | 说明 |
|------|------|------|
| `mock_paths` | 是 | mock 文件或目录的本地路径列表 |
| `screenshot_paths` | 否 | 页面截图路径列表；无截图可传 `[]` |
| `api_doc_source` | 是 | Torna **项目**链接（`http(s)://{host}/#/project/doc/{projectId}`）或本地完整 OpenAPI JSON/YAML |
| `output_dir` | 是 | 写入 `candidates.json` / `candidates.md` 的目录 |

示例 Torna 项目链接：`http://192.168.2.220:7700/#/project/doc/RqXBwzEl`  
单接口 `#/view/...` **不能**作为完整文档源。

## 执行步骤

1. 若 `api_doc_source` 是 Torna URL（`http`/`https`）：先调用 MCP **`test_torna_connection`**，参数 `doc_url` = 该链接。
   - `ok=false`：**立即停止**，汇报 `error`，提示检查 `TORNA_TOKEN`、网络与项目 ID；不要继续 `find_page_apis`。
   - `ok=true`：记下 `project_name`、`api_count`、`sample_paths`、`warnings`。
2. 调用 MCP **`find_page_apis`**：
   - `mock_paths`、`screenshot_paths`（无则 `[]`）、`api_doc_source`、`output_dir`
   - `vision_enabled`：有截图且已配置视觉凭据时为 `true`；无截图时设 `false`
   - 匹配策略为**混合**：先 path，再用 mock 字段名在文档参数/描述中打分补候选（`match_type=field` / `path+field`，见 `hit_fields`）
3. 汇报结果：
   - 连接测试摘要（若走了 Torna）
   - 统计：`matched` / `unmatched` / 警告
   - 产物路径：`candidates_path`（及对应 `candidates.md`）
   - **提醒用户编辑 `candidates.json` 中每条的 `selected`**，再使用 `/导出确认接口`
   - 若返回含 **`openapi_cache_path`**：明确告诉用户阶段 2 **优先**把该路径作为 `api_doc_source`，避免再次全量拉取 Torna
   - 若候选含 `hit_fields` / `score`：说明这些是字段反查命中，便于人工核对

## 产出

```
{output_dir}/
├── candidates.json              # 编辑 selected 用此文件
├── candidates.md                # 仅供阅读
└── full-openapi.from-torna.json # Torna 源时写出；阶段 2 优先复用
```
